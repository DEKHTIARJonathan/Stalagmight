# Task: Create useFocusTrap hook

## Description

Create a new React hook `useFocusTrap` in `src/hooks/useFocusTrap.ts` that traps keyboard focus (Tab / Shift+Tab) within a container element.

### Requirements

1. **API**: `useFocusTrap(containerRef: RefObject<HTMLElement>, active?: boolean)` — returns `{ pause(): void, resume(): void }`.
2. **Focusable element query**: Select all elements matching: `a[href], button:not(:disabled), input:not(:disabled), textarea:not(:disabled), select:not(:disabled), [tabindex]:not([tabindex="-1"])`. Exclude elements inside `[inert]` subtrees and elements with `display: none` or `visibility: hidden`.
3. **Tab cycling**: On Tab at the last focusable element, focus the first. On Shift+Tab at the first, focus the last.
4. **Pause/Resume**: When `pause()` is called, the keydown listener is removed. `resume()` re-attaches it. This is needed so the outer dialog can pause its trap when the nested alertdialog opens.
5. **Active flag**: When `active` is false (or the ref is null), the hook does nothing. Re-activates when `active` becomes true.
6. **Cleanup**: Remove keydown listener on unmount.
7. **Re-query on each Tab**: Focusable elements are re-queried on every Tab keypress (not cached), since dialog content may change dynamically (e.g., form validation reveals new buttons).

### File to create

`src/hooks/useFocusTrap.ts`

## Acceptance Criteria

- [ ] Hook file exists at `src/hooks/useFocusTrap.ts` and exports `useFocusTrap`.
- [ ] Tab at last focusable element wraps to first.
- [ ] Shift+Tab at first focusable element wraps to last.
- [ ] `pause()` stops trapping; `resume()` restarts it.
- [ ] Elements inside `[inert]` subtrees are excluded.
- [ ] `pnpm tsc --noEmit` passes.
