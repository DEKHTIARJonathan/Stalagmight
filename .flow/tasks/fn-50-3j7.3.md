# Task: Add initial focus logic to DialogWrapper

## Description

Implement automatic initial focus placement when a dialog opens, using a heuristic that distinguishes form dialogs from non-form dialogs.

### Requirements

1. **Focus heuristic** (in priority order):
   a. If the dialog body contains a `<form>`, focus the first visible `<input>` or `<textarea>` within it.
   b. If any element has `[data-autofocus]`, focus that element.
   c. Focus the first `<button>` that is NOT the close (x) button (identified by `aria-label="Close dialog"`).
   d. Fallback: focus the dialog container element itself (it should have `tabindex="-1"` for this case).
2. **Timing**: Run focus logic in a `useEffect` after mount, with a `requestAnimationFrame` to ensure the DOM is painted.
3. **No flash**: The focus should not cause visible scroll jumps or layout shifts.

### Files to modify

- `src/components/Dialogs/DialogWrapper.tsx`

## Acceptance Criteria

- [ ] Opening a form dialog (e.g., EditSectionDialog) focuses the first input.
- [ ] Opening a non-form dialog focuses the primary action button.
- [ ] `[data-autofocus]` attribute is respected when present.
- [ ] Dialog container has `tabindex="-1"` as fallback target.
- [ ] `pnpm tsc --noEmit` passes.
