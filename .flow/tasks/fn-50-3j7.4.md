## Approach

### Initial focus (on mount)

Heuristic priority order:
1. Element with `[data-autofocus]` (explicit override — highest priority)
2. First visible `<input>`, `<textarea>`, or `<select>` in the dialog body (form dialogs)
3. Element with `[data-primary-action]` (marks the primary/danger action button — deterministic identification)
4. First `<button>` that is NOT the close X button
5. Fallback: the close X button

- Run in `useEffect` after mount, with `requestAnimationFrame` for DOM readiness
- Place cursor at end of text inputs (no auto-select)
- Remove `autoFocus` from `NewProjectDialog` (line 80) and `NewProjectForImportDialog` (line 111) — replaced by centralized logic
- Cleanup: clear pending rAF on unmount (React Strict Mode double-invoke safety)

### Add `data-primary-action` to dialog buttons

Add `data-primary-action` attribute to the primary/danger action button in each dialog that has action buttons. This ensures deterministic identification regardless of DOM order:

- `ConfirmDialog.tsx`: Delete button (variant="danger")
- `NewProjectDialog.tsx`: Create Project button (variant="primary")
- `ExportDialog.tsx`: Export button (variant="primary")
- `EditShotDialog.tsx`: Save button (variant="primary")
- `EditSectionDialog.tsx`: Save button (variant="primary")
- `EditStationDialog.tsx`: Save button (variant="primary")
- `OverwriteConfirmDialog.tsx`: Overwrite button (variant="danger")
- `UnsavedChangesDialog.tsx`: Discard Changes button (variant="danger")
- `DrawShotDialog.tsx`: Create Shot button (variant="primary")
- `MergeDialog.tsx`: Merge button (variant="primary")
- `ClosureDialog.tsx`: Apply button (variant="primary")

Alternatively, if the `Button` component has a `variant` prop, consider adding `data-primary-action` automatically in the Button component when `variant="primary"` or `variant="danger"`. This avoids touching every dialog individually.

### Return focus (on unmount)

- On mount: store `document.activeElement` in a ref
- On unmount: call `.focus()` on stored element if it is still in the DOM (check `document.body.contains(element)`)
- If stored element was removed: do nothing, let browser decide
- Remove `inert` from app root BEFORE restoring focus (inert elements cannot receive focus) — `popDialog()` (named export from `src/utils/dialogStack.ts`) handles inert removal automatically in its cleanup
