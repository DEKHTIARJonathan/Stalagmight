# fn-34-0k5.2 Playwright e2e tests for section dropdown hover highlighting

## Description

Add Playwright e2e tests covering section dropdown hover highlighting: mouse hover triggers map highlight, keyboard navigation triggers map highlight, and dropdown close clears map highlight.

**Size:** M
**Files:**
- `e2e-playwright/section-dropdown-hover.spec.ts` (new test file)
- `docs/TESTING.md` (add Select hover test patterns)

## Approach

### Test file

Create `e2e-playwright/section-dropdown-hover.spec.ts` following patterns from `section-highlighting.spec.ts`:
- Use `setupMockedPage(page)` + `createProject(page)` + `seedProjectWithSections(page, sections)` fixtures
- Use `waitForMapReady(page)` before assertions

### Test cases

1. **Mouse hover → map highlight**: Open section dropdown, hover an option, verify `hoveredSectionId` in uiStore matches the hovered section. Use `pollHoveredSectionId()` or `page.evaluate()` for store access.

2. **Keyboard nav → map highlight**: Open section dropdown, press ArrowDown, verify `hoveredSectionId` updates. Press ArrowDown again, verify it changes.

3. **Close → highlight cleared**: Open dropdown, hover an option (verify highlight set), then:
   - Press Escape → verify `hoveredSectionId` is null
   - Click outside → verify `hoveredSectionId` is null
   - Select an option → verify `hoveredSectionId` is null

4. **Section ID 0**: If test data includes section 0, verify it highlights correctly (truthiness edge case).

### TESTING.md update

Add a "Select Hover Callback Testing" subsection under the existing hover testing patterns. Document:
- How to verify `onOptionHover` fires via store state checks
- Pattern for polling hover state changes
- Note about Playwright hover() reliability (use focus-based approach if unreliable per project memory)

### Key context

- **Playwright hover() unreliable**: Project memory notes this. Use `page.evaluate()` to dispatch mouseover/mouseout events if `.hover()` doesn't work, or use focus-based testing.
- **React onMouseEnter/Leave**: Requires dispatching `mouseover`/`mouseout` with `bubbles: true`, not `mouseenter`/`mouseleave` (project memory pitfall).
- **State polling**: Use `expect.poll()` for async state changes, following `section-highlighting.spec.ts` patterns.
- **Test data**: Use `seedProjectWithSections` to create sections with known IDs for predictable assertions.
