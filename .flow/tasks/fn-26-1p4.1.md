## Description

Add view-mode-aware marker visibility to the Global View. In survey mode, markers should be hidden for systems whose geometry has loaded successfully, and visible (with spinners or error indicators) for systems still loading or failed. In markers mode, all markers remain visible as today.

**Size:** M
**Files:** `src/components/GlobalView/GlobalViewMap.tsx`

## Approach

### viewMode ref for creation effect

Add a `viewModeRef` that tracks viewMode without being a dependency of the creation effect. Pattern: `const viewModeRef = useRef(viewMode); viewModeRef.current = viewMode;`

In the creation effect (`GlobalViewMap.tsx:760-886`), after creating each marker element, set initial visibility using `viewModeRef.current`:
- If `viewModeRef.current === 'survey'` AND `loadingState === 'loaded'` → `el.style.display = 'none'`
- Otherwise → `el.style.display = 'flex'` (existing behavior, already set via cssText)

Do NOT add `viewMode` to the creation effect's dependency array — the ref avoids unnecessary recreation on mode toggle.

### New visibility-sync effect

Add a new `useEffect` that reacts to `viewMode` and `geometryStates` changes:
- Dependencies: `viewMode`, `geometryStates`, `mapLoaded`
- Iterate `markersRef.current` entries
- For each marker, check view mode and geometry state via `geometryStates.get(filePath)?.state`
- Set `el.style.display = 'none'` if survey mode AND state is `'loaded'`; otherwise `'flex'`
- Do NOT update colors or remove spinners — the creation effect (triggered by `geometryStates` dep) handles recreation with correct visual state, and the styles effect handles color updates

### Why no color/spinner management in visibility-sync

When `geometryStates` changes (e.g., loading→loaded), the creation effect already recreates all markers with correct spinners and colors. The visibility-sync effect also runs and sets `display` accordingly. The styles effect (`GlobalViewMap.tsx:888-907`) handles color updates respecting selection state. The visibility-sync effect's sole job is `display` toggling.

## Key context

- `markersRef` at `GlobalViewMap.tsx:127` stores all Marker instances in a Map keyed by file path.
- Marker element inline style at `GlobalViewMap.tsx:800` uses `display: flex`.
- **Creation effect** at `GlobalViewMap.tsx:760-886` depends on `[gpsProjects, selectedProjectId, mapLoaded, onProjectSelect, onProjectOpen, geometryStates]` — already recreates markers on geometry state changes.
- **Styles effect** at `GlobalViewMap.tsx:888-907` depends on `[selectedProjectId, geometryStates]` — handles selection (blue), error (red), default (teal) colors.
- Geometry loading state: `geometryStates.get(project.file_path)?.state ?? 'idle'`.
- View mode from `useViewMode()` hook (`ViewModeToggle.tsx:20-44`).
- Memory pitfall: useEffect syncing state to ref needs `mapLoaded` in deps to re-run after ref becomes valid.
