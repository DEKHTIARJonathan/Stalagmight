# Task: Verify SettingsSidebar roving tabindex compatibility

## Description

Ensure the new focus trap in DialogWrapper does not interfere with the roving tabindex keyboard navigation in SettingsSidebar.tsx (used inside SettingsDialog).

### Requirements

1. **Manual verification**: Open SettingsDialog, verify:
   - Arrow Up/Down moves focus between category tabs.
   - Home/End jumps to first/last tab.
   - Enter/Space activates the focused tab.
   - Tab moves focus OUT of the sidebar to the next focusable element in the dialog (within the focus trap boundary).
   - Shift+Tab from the sidebar content returns to the sidebar tabs.
2. **Automated test**: Write a Playwright test that opens SettingsDialog and verifies arrow key navigation still works on the sidebar tabs.
3. **Root cause check**: Confirm that `[tabindex="-1"]` tabs are excluded from the focus trap's focusable element query (they should be, since the query excludes `[tabindex="-1"]`).

### Files to verify

- `src/components/Dialogs/SettingsSidebar.tsx` — read only, should NOT need changes.
- `src/hooks/useFocusTrap.ts` — verify the focusable element selector.

## Acceptance Criteria

- [ ] Arrow key navigation works in SettingsSidebar when focus trap is active.
- [ ] Only the active tab (tabindex=0) is part of the Tab cycle; inactive tabs (tabindex=-1) are skipped.
- [ ] Playwright test confirms arrow key navigation in SettingsSidebar.
- [ ] `pnpm test:ui` passes.
