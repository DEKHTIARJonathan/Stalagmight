## Description

Migrate DialogWrapper from inline rendering to React portal, add dialog-root element to index.html, and wire dialogStack for inert management.

**Size:** M
**Files:** `index.html`, `src/components/Dialogs/DialogWrapper.tsx`

## Approach

1. Add `<div id="dialog-root"></div>` to `index.html` after `<div id="root"></div>` (line 10)
2. In DialogWrapper, wrap the entire return in `createPortal(..., document.getElementById('dialog-root')!)`
3. On mount: call `dialogStack.pushDialog(dialogRef.current)` to register and set `inert` on siblings
4. On unmount: call `dialogStack.popDialog(dialogRef.current)` to unregister and restore `inert`
5. Move Escape handler from `document.addEventListener('keydown', ..., true)` (capture phase, lines 73-93) to `onKeyDown` on the dialog container element
6. Add `tabindex="-1"` to the dialog container div so it can receive keyboard events when focus is on child elements (events bubble up)
7. The existing `useKeyboardShortcuts` global handler (line 298-324 of `src/hooks/useKeyboardShortcuts.ts`) already checks `event.defaultPrevented` at line 301 — DialogWrapper's `e.preventDefault()` in onKeyDown will prevent double-firing. No changes to useKeyboardShortcuts needed.

## Key context

- React synthetic `e.preventDefault()` sets `defaultPrevented` on the native event — native handlers see it
- Events inside React portals bubble up the React component tree, not the DOM tree — context providers still work
- Existing portal patterns: Toast (`App.tsx:568`), Select (`Select.tsx:571`), UndoHistoryDropdown (`UndoHistoryDropdown.tsx:127`)
- Toast portals to `document.body`, not `dialog-root` — won't be affected by inert management
- Current Escape handler is at `DialogWrapper.tsx:73-93` (capture phase on document)
- Memory pitfall: "Portal dropdown width measurement needs visibility:hidden pass" — not applicable here since dialogs are always visible
