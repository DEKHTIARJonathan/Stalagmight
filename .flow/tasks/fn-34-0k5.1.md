## Description

Add `onOptionHover?: (value: string | null) => void` callback prop to the Select component. Fire the callback on mouse hover and keyboard navigation (ArrowDown, ArrowUp, Home, End). Fire `null` on all six dropdown close paths. Wire the callback in DataTable's section dropdown to `setHoveredSectionId` for map highlighting.

**Size:** M
**Files:**
- `src/components/common/Select.tsx` (add prop, modify event handlers, add unmount cleanup)
- `src/components/SingleSystemView/DataTable.tsx` (wire onOptionHover to setHoveredSectionId)

## Approach

### Select.tsx changes

1. Add `onOptionHover?: (value: string | null) => void` to `SelectProps` interface (after line 37)

2. **Mouse hover**: In `renderOption()`, extend the existing `onMouseEnter` handler at line 324. After setting `highlightedIndex`, call `onOptionHover?.(option.value)`. The existing `!option.disabled` guard already applies.

3. **Keyboard navigation**: In the `onKeyDown` handler (lines 219-294), the current code uses `setHighlightedIndex(prev => ...)` functional updaters (lines 229, 239). To avoid reading stale `highlightedIndex`, **compute `nextIndex` from the current state first**, then call both `setHighlightedIndex(nextIndex)` and `onOptionHover?.(flatOptions[nextIndex]?.value)`. Guard with `nextIndex >= 0`. This applies to ArrowDown, ArrowUp, Home, and End cases.

4. **ArrowDown/Up opening the dropdown**: When the dropdown is closed and ArrowDown/Up opens it (line 226), the dropdown opens and auto-highlights an option. Compute the initially highlighted option using the same logic as the existing open handler: if the selected option exists and is enabled, use its index; otherwise use the first enabled option index (reuse `findSelectedIndex` + first-enabled fallback at lines 152-166). Fire `onOptionHover` with that option's value. This is user-initiated navigation, distinct from click-to-open which does not fire the callback.

5. **All six close paths must fire `onOptionHover(null)`:**
   - `handleSelect()` — option selected via click/Enter/Space
   - Outside-click handler (lines 136-148)
   - Escape key handler (lines 276-285)
   - Tab key handler (lines 287-292)
   - **Trigger-toggle-to-close** — clicking trigger button while open (`Select.tsx:362`). When `isOpen` is true and the click closes, call `onOptionHover?.(null)`
   - **Component unmount** — if Select unmounts while open, fire `onOptionHover?.(null)` via cleanup effect. Track both `onOptionHover` and `isOpen` in refs to avoid stale closures. Guard the cleanup: only fire if `isOpenRef.current` is true at unmount time.

6. **No intermediate nulls**: Call `onOptionHover` directly from event handlers, not from a `useEffect` on `highlightedIndex`. This prevents render-cycle delays and intermediate null states.

### DataTable.tsx changes

1. Create `handleSectionHover` callback that:
   - When value is non-null: converts string to number via `Number(value)`, calls `setHoveredSectionId(sectionId)`
   - When value is null: calls `setHoveredSectionId(null)`
   - Tracks last hover ID in a ref (matching `SectionsPanel.tsx:12-30` pattern)

2. Pass `onOptionHover={handleSectionHover}` to the section Select at lines 429-434

3. Add ref-based unmount cleanup: track last-hovered ID in `lastHoveredSectionIdRef`, clear on unmount only if store value matches (follow `SectionsPanel.tsx:12-30` exactly)

4. **DataTable collapse**: When `dataTableOpen` becomes false, Select unmounts. Select's own unmount cleanup (close path #6) fires `onOptionHover(null)`, which DataTable's handler receives and clears hover state. No additional DataTable-level cleanup needed beyond the ref-based guard.

## Key context

- **SectionId can be 0**: Use `!== null` checks, never truthiness. `Number("0")` correctly returns 0.
- **Stale closures pitfall**: Track `onOptionHover` and `isOpen` in refs for the unmount cleanup effect (project memory).
- **Stale highlightedIndex**: Current ArrowDown/Up uses `setHighlightedIndex(prev => ...)`. Must compute `nextIndex` before calling `onOptionHover` to avoid reading stale state.
- **flatOptions**: Select.tsx already flattens grouped options into `flatOptions` array. Use this to resolve option values from `highlightedIndex`.
- **Initial highlight computation on arrow-open**: Reuse the logic at Select.tsx lines 152-166 — find selected option index, fallback to first enabled. Fire `onOptionHover` with that option's value.
