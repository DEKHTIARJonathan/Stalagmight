# Backend - MoveSegment Command + Query IPCs + execute_batch IPC

## Overview

Add a `MoveSegment` command to the Rust backend that moves all connected sections (the entire segment) by an offset. Expose two new read-only Tauri IPC commands for the frontend (`get_connected_section_ids`, `get_anchored_section_ids`). Also create and register the `execute_batch` Tauri IPC command — the internal `Command::Batch` and `execute_batch()` logic already exist (at `commands.rs:642`) but no Tauri command wraps them. The frontend `projectStore.ts:855` already has a `executeBatch()` method calling `invoke('execute_batch', ...)` — it just needs the backend endpoint.

## Steps

### 2a. Add Command variant (`src-tauri/src/core/command.rs:88`)

```rust
MoveSegment {
    section_id: SectionId,  // any section in the segment
    offset: Coordinates,
},
```

### 2b. Implement command (`src-tauri/src/core/state/commands.rs`)

New method `move_segment()`:
1. Lock project
2. Call `project.get_connected_section_ids(section_id)` (existing at `project.rs:250` — BFS over merges + closures) to find all connected sections
3. Apply offset to every section in the connected set via `project.section_offsets`
4. Call `project.touch()`

### 2c. Wire into dispatch (`src-tauri/src/core/state/commands.rs:82`)

Add match arm: `Command::MoveSegment { section_id, offset } => self.move_segment(*section_id, *offset)`

### 2d. Undo support (`src-tauri/src/core/state/undo.rs`)

Undo data: `UndoData::InverseCommand(Command::MoveSegment { section_id, offset: -offset })` (same pattern as MoveSection).

Add to `execute_undo_command()` match arm (~line 835).

### 2e. Tauri command — move_segment (`src-tauri/src/commands/section.rs`)

```rust
#[tauri::command]
pub fn move_segment(state: State<AppState>, section_id: SectionId, offset: Coordinates) -> CommandResult {
    state.execute(Command::MoveSegment { section_id, offset })
}
```

Register in `src-tauri/src/lib.rs` alongside `move_section`.

### 2f. Tauri command — execute_batch (`src-tauri/src/commands/section.rs` or a new `batch.rs`)

The internal `Command::Batch { commands: Vec<Command> }` (at `command.rs:98`) and `execute_batch()` (at `commands.rs:642`) already exist, but no Tauri IPC wraps them. The frontend at `projectStore.ts:855` already calls `invoke('execute_batch', { commands })` — it's currently dead code because the backend endpoint is missing.

Create and register a Tauri command:

```rust
#[tauri::command]
pub fn execute_batch(state: State<AppState>, commands: Vec<Command>) -> CommandResult {
    state.execute(Command::Batch { commands })
}
```

Register in `src-tauri/src/lib.rs`. Note: `Command` must be deserializable from the JSON the frontend sends (which uses the `BatchCommand` TypeScript type). Ensure `Command` derives `Deserialize` for the variants the frontend needs: at minimum `MoveStation`, `MoveSection`, `CreateSection`, `MergeStations`, `SetZeroDatum`.
