# Frontend - Move Tool Handlers

## Overview

Wire up the `move_segment` and `move_shot` tools in the frontend so that clicking/dragging on the map performs the correct move operations. Extend MoveDragState, add handlers for station/shot clicks, implement real-time drag preview for segment moves (new behavior — existing Move Section has no preview), and handle drag end with appropriate backend calls.

## Design Decisions (from interview)

- **Move Segment drag preview**: Real-time shift of ALL connected sections during drag (not ghost/translucent). Connected section IDs are fetched once at drag start via `projectStore.getConnectedSectionIds(sectionId)` (Tauri IPC added in Task 2, wraps `Project::get_connected_section_ids()` at `project.rs:250`). During drag, a temporary visual offset is applied to all connected sections in the render layer. No backend calls occur until drag end.
- **Existing drag pattern note**: The current Move Section/Station drag (MapCanvas.tsx lines 273-529) does NOT have a visual preview — it tracks `startLngLat`/`currentLngLat` but only commits on release. The segment preview is NEW behavior.
- **Anchored segments**: When Move Segment tool is active, sections in anchored segments are **faded** and **non-interactive**. Anchored section IDs are fetched via `projectStore.getAnchoredSectionIds()` (Tauri IPC added in Task 2, wraps `Project::section_has_zero_datum()` at `project.rs:328`). This is called once when the tool becomes active and cached until tool changes.
- **Move Shot**: Moves BOTH stations of the clicked shot. Station 0 (section origin) is allowed. Virtual shots are also moveable.
- **Atomic undo (mandatory)**: Move Shot MUST use the existing `execute_batch` Tauri IPC (already exposed, called from `projectStore.ts:855`) with the existing `Command::Batch` (defined at `command.rs:98`, executed at `commands.rs:642`). There is NO fallback to sequential `moveStation` calls.

## Steps

### 4a. Extend BatchCommand type (`src/types/commands.ts:68`)

The existing `BatchCommand` union type does not include a `move_station` variant. Add it:

```typescript
| { type: 'move_station'; station_ref: StationRef; offset: Coordinates }
```

This must match the Rust `Command::MoveStation` variant. The existing `executeBatch()` in `projectStore.ts:855` already calls `invoke('execute_batch', { commands })` so no store changes needed for this.

### 4b. Move Segment drag start (`src/hooks/useMapTools.ts`)

In `handleStationClick`, add `move_segment` case:
- Call `projectStore.getAnchoredSectionIds()` (or use cached value) to check if the station's section is anchored. If so, do nothing (silent no-op).
- Get `sectionId` from station ref
- Call `onMoveDragStart({ type: 'segment', sectionId, screenX, screenY })`

### 4c. Anchored segment fading (MapCanvas or SurveyLayer)

When `activeTool === 'move_segment'`:
- Call `projectStore.getAnchoredSectionIds()` to get the set of anchored section IDs. Cache this in a `useMemo` or `useEffect` — only refetch when tool becomes `move_segment` or project state changes.
- Apply faded/reduced-opacity styling to features belonging to anchored sections
- Suppress cursor change to 'move' when hovering over anchored segment features
- On click of anchored station: silent no-op (no drag starts, no toast)

### 4d. Move Segment real-time drag preview (MapCanvas.tsx)

This is new behavior — no existing pattern to follow for visual preview during drag.

1. **At drag start** (`handleMoveDragStart` in MapCanvas, ~line 273):
   - When `type === 'segment'`, call `projectStore.getConnectedSectionIds(sectionId)` to get the full set of connected section IDs
   - Filter out any anchored section IDs (they don't move)
   - Store the resulting set in MoveDragState as `connectedSectionIds: number[]`

2. **During drag** (`handleMoveDragMove` / `onMouseMove`, ~line 486):
   - Compute `dragOffset = currentLngLat - startLngLat` (as meters, using existing `mapCoordsToMeters()`)
   - Pass `{ dragOffset, connectedSectionIds }` to the render layer as React state or prop
   - The render layer (SurveyLayer or direct MapCanvas drawing) applies this offset to ALL survey features (lines, stations, labels) for sections in `connectedSectionIds`
   - This is purely visual — transform the rendered coordinates, don't mutate project state

3. **At drag end** (`handleMoveDragEnd`, ~line 504):
   - Clear the temporary visual offset (set `connectedSectionIds` to null/empty, `dragOffset` to zero)
   - Commit the final offset via `projectStore.moveSegment(sectionId, offset)`

### 4e. Move Shot drag (`src/hooks/useMapTools.ts`)

In `handleShotClick`, add `move_shot` case:
- Find both stations of the shot (from = shotIndex, to = shotIndex + 1)
- Call `onMoveDragStart({ type: 'shot', sectionId, shotIndex, screenX, screenY })`

Needs `MoveDragStartData` extended to include `type: 'segment' | 'shot'` and `shotIndex`.

### 4f. Extend MoveDragState (`src/components/Map/MapCanvas.tsx:28`)

```typescript
interface MoveDragState {
  type: 'section' | 'station' | 'segment' | 'shot';
  sectionId?: number;
  stationRef?: { section_id: number; station_index: number };
  shotIndex?: number;  // for 'shot' type - identifies from/to stations
  connectedSectionIds?: number[];  // for 'segment' type - computed at drag start
  startLngLat: { lng: number; lat: number };
  currentLngLat: { lng: number; lat: number };
}
```

### 4g. Handle drag end (`src/components/Map/MapCanvas.tsx` ~line 504)

In `handleMoveDragEnd`:
- `'segment'`: clear temporary visual offset, then call `projectStore.moveSegment(sectionId, offset)`
- `'shot'`: move both stations atomically via `projectStore.executeBatch()` (existing at `projectStore.ts:855`). This is the ONLY path, no fallback:

```typescript
await projectStore.executeBatch([
  { type: 'move_station', station_ref: fromRef, offset },
  { type: 'move_station', station_ref: toRef, offset },
]);
```

Where `fromRef = { section_id, station_index: shotIndex }` and `toRef = { section_id, station_index: shotIndex + 1 }`.

### 4h. Update drag indicator text (~line 1888)

Show "Move Segment" or "Move Shot" as appropriate based on `moveDrag.type`.
