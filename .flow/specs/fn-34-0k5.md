# Data Table Section Dropdown Hover Highlights Section on Map

## Overview

When browsing sections in the DataTable's section dropdown, users lack spatial context for which section they're about to select. This feature adds an `onOptionHover` callback prop to the `Select` component so hovering dropdown options (mouse or keyboard) highlights the corresponding section on the map — matching the existing SectionsPanel hover-to-highlight behavior.

## Scope

**In scope:**
- New `onOptionHover?: (value: string | null) => void` prop on Select component
- Mouse hover on options fires `onOptionHover` with the option's value
- Arrow key / Home / End keyboard navigation fires `onOptionHover` with the highlighted option's value
- ArrowDown/Up opening dropdown from closed state fires `onOptionHover` with the initially highlighted option's value (computed via selected-index or first-enabled fallback)
- Moving between options fires new value directly (no intermediate null)
- Disabled options do not fire `onOptionHover`
- All 6 dropdown close paths fire `onOptionHover(null)`: option selected, click outside, Escape, Tab, trigger-toggle-to-close, component unmount
- Component unmount cleanup guards on `isOpenRef` — only fires if dropdown was open
- DataTable wires `onOptionHover` to `setHoveredSectionId` for the section dropdown
- Ref-based cleanup on unmount (matching SectionsPanel pattern)
- Playwright e2e tests for hover, keyboard nav, and close-clears behavior

**Out of scope:**
- Debouncing/throttling the callback
- Changes to other Select usage sites (only DataTable section dropdown wires the callback)
- SPEC.md or architecture doc updates (minor feature, not worth doc churn)

## Approach

### Select component changes

Add `onOptionHover` to `SelectProps` interface (after existing props at `Select.tsx:18-37`).

**Mouse hover**: In `renderOption()`, the existing `onMouseEnter` at line 324 already sets `highlightedIndex`. Add `onOptionHover?.(option.value)` call in the same handler, guarded by `!option.disabled`.

**Keyboard navigation**: In the `onKeyDown` handler (lines 219-294), the current code uses `setHighlightedIndex(prev => ...)` functional updaters (lines 229, 239). To avoid reading stale `highlightedIndex`, compute `nextIndex` from the current state before calling both `setHighlightedIndex(nextIndex)` and `onOptionHover?.(flatOptions[nextIndex]?.value)`. This applies to ArrowDown, ArrowUp, Home, and End cases.

**ArrowDown/Up opening the dropdown**: When the dropdown is closed and ArrowDown/Up opens it (line 226), compute the initially highlighted option using the same logic as the existing open handler: if the selected option exists and is enabled, use its index; otherwise use the first enabled option index (reuse logic at lines 152-166). Fire `onOptionHover` with that option's value. This is user-initiated navigation; click-to-open does not fire the callback.

**No intermediate nulls**: Fire the new value directly from event handlers — do NOT use a `useEffect` watching `highlightedIndex`.

**Close paths — ALL six paths must fire `onOptionHover(null)`:**
1. `handleSelect()` — option selected via click/Enter/Space
2. Outside-click handler (lines 136-148)
3. Escape key handler (lines 276-285)
4. Tab key handler (lines 287-292)
5. **Trigger-toggle-to-close** — clicking the trigger button while open (`Select.tsx:362`)
6. **Component unmount** — cleanup effect fires `onOptionHover?.(null)` only if `isOpenRef.current` is true. Track both `onOptionHover` and `isOpen` in refs to avoid stale closures.

### DataTable wiring

In `DataTable.tsx`, add an `onOptionHover` handler to the section Select (lines 429-434). The handler converts the string value to a number via `Number(value)` and calls `setHoveredSectionId`. When value is null, call `setHoveredSectionId(null)`.

Follow the ref-based cleanup pattern from `SectionsPanel.tsx:12-30`: track the last hover ID in a ref, clear on unmount only if the store still has the ID this component set.

**DataTable collapse cleanup**: The section Select at line 425 is conditionally rendered (only when `dataTableOpen` is true). When `dataTableOpen` becomes false, the Select unmounts. The Select's own unmount cleanup (close path #6) handles firing `onOptionHover(null)`, which DataTable's handler receives and clears the hover state.

### Key reuse points

- Hover-to-highlight pattern: `SectionsPanel.tsx:110-122` (mouse enter/leave handlers)
- Ref-based cleanup: `SectionsPanel.tsx:12-30` (lastHoveredIdRef + unmount effect)
- Initial highlight computation: `Select.tsx:152-166` (find selected or first enabled)
- uiStore hover state: `uiStore.ts:541,544` (hoveredSectionId + setter)
- MapCanvas sync: `MapCanvas.tsx:709-714` (useEffect syncing hoveredSectionId to SurveyLayer)
- Keyboard nav: `Select.tsx:219-294` (existing ArrowDown/Up/Home/End handlers)

## Risks / Dependencies

- **fn-31-mhl overlap**: Both modify `Select.tsx`. Changes are orthogonal (portal rendering vs. hover callback prop). Whichever lands first, the other must resolve merge conflicts around the props interface and close handlers.
- **fn-39-5zr dependency**: Section highlighting pipeline. The spec states "section highlighting already works visually" — this epic can land independently; the callback fires but the visual effect may not appear until fn-39-5zr completes.
- **SectionId can be 0**: All comparisons must use `!== null`, never truthiness checks.
- **Stale closures**: Track `onOptionHover` and `isOpen` in refs for the unmount cleanup effect (project memory pitfall).
- **Stale highlightedIndex**: Current ArrowDown/Up uses functional updaters. Must compute `nextIndex` before calling `onOptionHover`.
