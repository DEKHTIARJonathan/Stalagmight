# Data Table Section Dropdown Hover Highlights Section on Map

## Problem

When using the DataTable's section dropdown to browse sections, the user has no spatial context for which section they're about to select. Hovering a section in the dropdown should highlight it on the map, matching the existing behavior in SectionsPanel where hovering a section row highlights it on the map.

## Key Decisions

- **General-purpose Select API**: Add a reusable `onOptionHover(value: string | null)` callback prop to the `Select` component rather than a DataTable-specific solution
- **Single callback with null**: `onOptionHover` fires with the option's `value` string on hover, and `null` when the mouse leaves all options or the dropdown closes. No separate `onOptionLeave` callback
- **Both mouse and keyboard**: Arrow key navigation through dropdown options also triggers `onOptionHover`, not just mouse hover
- **No intermediate nulls**: Moving between options fires the new value directly without an intermediate `null` (prevents map highlight flicker)
- **Skip disabled options**: Disabled options do not trigger `onOptionHover`, consistent with existing `highlightedIndex` behavior
- **Clear on close**: When the dropdown closes (select, click outside, Escape), fire `onOptionHover(null)` to clear the map highlight
- **Clear to null on close**: No tracking/restoration of previous `hoveredSectionId`; just clear to `null`
- **No extra dropdown styling**: The dropdown's existing hover/highlight CSS is sufficient; the map highlight is the visual feedback
- **Fire regardless of map visibility**: Always call the callback; if the map isn't visible it's a no-op
- **Identical to SectionsPanel**: Same highlight style, same state mechanism (`hoveredSectionId` in uiStore), same ref-based cleanup pattern
- **No exclusions**: Every option in the section dropdown corresponds to a real section
- **Section highlighting already works visually**: The existing `setHoveredSection` pipeline through MapCanvas → SurveyLayer already produces a visible highlight; docs noting it was unimplemented are stale
- **E2e tests included**: Add Playwright tests covering mouse hover, keyboard nav, and close-clears-highlight

## Edge Cases

- **SectionId can be 0**: Always use `!== null` checks, never truthiness, when working with section IDs
- **Hover conflict**: If SectionsPanel or another component set `hoveredSectionId`, the dropdown hover overwrites it. On dropdown close, clear to `null` (no restore)
- **Dropdown close paths**: Must fire `null` on all close paths: option selected, click outside, Escape key, Tab key
- **Unmount cleanup**: Use ref-based cleanup pattern (track last hovered ID in ref, only clear if store's current value matches) to prevent clearing another component's hover
- **Map not loaded**: MapCanvas effect depends on `mapLoaded`; if map isn't loaded yet, the effect safely no-ops

## Acceptance

- [ ] Select component has `onOptionHover?: (value: string | null) => void` prop
- [ ] Mouse hover on dropdown option fires `onOptionHover` with the option's value
- [ ] Arrow key navigation fires `onOptionHover` with the highlighted option's value
- [ ] Moving between options fires new value directly (no intermediate null)
- [ ] Disabled options do not fire `onOptionHover`
- [ ] Dropdown close (any path) fires `onOptionHover(null)`
- [ ] DataTable wires `onOptionHover` to `setHoveredSectionId` for the section dropdown
- [ ] Hovering a section in the dropdown highlights it on the map identically to SectionsPanel hover
- [ ] Dropdown close clears the section highlight on the map
- [ ] Ref-based cleanup on unmount prevents stale hover state
- [ ] Playwright e2e tests cover: mouse hover → map highlight, keyboard nav → map highlight, close → highlight cleared
