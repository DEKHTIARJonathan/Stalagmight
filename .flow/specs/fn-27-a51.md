# Settings Panel Static Height with Scrollable Content

## Problem

The settings dialog currently uses `max-h-[90vh]`, which causes the dialog to grow and shrink depending on which category is active. Categories with few fields (e.g., Units, Validation) produce a shorter dialog, while content-heavy categories (e.g., Map, Display, Shortcuts) make it taller. This height shifting when switching categories is visually jarring and inconsistent.

## Solution

Make the settings dialog a fixed-size panel that maintains the same dimensions regardless of active category. Content overflows via scrolling within the content area.

## Key Decisions

- **Height**: Use CSS `clamp(500px, 80vh, 800px)` — viewport-relative with pixel bounds
- **Width**: Fixed at `800px` with responsive fallback via `min(800px, 95vw)`
- **Responsive fallback**: Pure CSS using `min()` / `clamp()` functions — no JS viewport detection needed
- **Both dimensions fixed**: The dialog is fully static (both width and height), not just height
- **Scroll reset**: When switching categories, scroll position resets to top via `scrollTop = 0` on a ref (not re-keying the container)
- **Short content alignment**: Content is top-aligned (no vertical centering when content doesn't fill the area)
- **Scrollbar styling**: Keep existing custom scrollbar styling unchanged (dark track, teal hover thumb)
- **No animation changes**: This is a layout fix only, no transition changes
- **Sidebar**: Stays at `w-[150px]` — unchanged
- **Cleanup**: Remove redundant `min-h-[500px]` from inner container (clamp handles the minimum)
- **Minimum width**: Decrease to `min-w-[500px]` (from 600px)

## DialogWrapper API Change

Add a generic `fixedSize` prop to `DialogWrapper` so any dialog can opt in:

```tsx
interface FixedSize {
  width: string;   // e.g., '800px'
  height: string;  // e.g., '80vh'
}

// Usage:
<DialogWrapper
  fixedSize={{ width: '800px', height: '80vh' }}
  ...
>
```

- **Both width and height are required** when using `fixedSize` — no partial specification
- **`fixedSize` overrides both `size` and `maxHeight`** props when provided — clean separation, no ambiguity
- **Responsive fallback built in**: DialogWrapper applies CSS `min()` / `clamp()` so fixed-size dialogs gracefully degrade on small viewports

## Edge Cases

- **Small viewport**: Dialog falls back to responsive sizing when window is smaller than fixed dimensions (via CSS `min(800px, 95vw)` for width, `clamp(500px, 80vh, 800px)` for height)
- **Category switch scroll**: Scroll position resets to top on every category change via imperative `scrollTop = 0`
- **Short content categories**: Content stays top-aligned with empty space below — no centering
- **Existing dialogs unaffected**: Only dialogs that pass `fixedSize` get the new behavior; all others keep current `size` + `maxHeight` behavior
