# Settings Panel Static Height with Scrollable Content

## Problem

The settings dialog uses `max-h-[90vh]`, causing height to shift when switching categories. Categories with few fields (Units, Validation) produce a shorter dialog; content-heavy categories (Map, Shortcuts) make it taller. This is visually jarring.

## Solution

Make the settings dialog a fixed-size panel: `min(800px, 95vw)` wide × `clamp(500px, 80vh, 800px)` tall. Content overflows via scrolling within the content area. Scroll resets to top on category switch.

Add a generic `fixedSize` prop to `DialogWrapper` so any dialog can opt into fixed dimensions.

## Key Decisions

- **Height**: `clamp(500px, 80vh, 800px)` — viewport-relative with pixel bounds
- **Width**: `min(800px, 95vw)` — responsive fallback via CSS
- **fixedSize prop**: Both width and height required; overrides `size` and `maxHeight`
- **Scroll reset**: `scrollTop = 0` on a ref targeting the content div, not re-keying
- **Short content**: Top-aligned (no vertical centering)
- **Cleanup**: Remove `min-h-[500px]` from inner container, decrease `min-w` to `500px`
- **Tailwind syntax**: Use underscores in arbitrary values: `h-[clamp(500px,_80vh,_800px)]`
- **Same-category click**: Still resets scroll (simplest behavior)

## Key Context

- `DialogWrapper.tsx` — dialog wrapper with `size`, `maxHeight`, `overflow` props (line ~16-30)
- `SettingsDialog.tsx` — uses `size="4xl"`, `maxHeight="max-h-[90vh]"`, `overflow="hidden"` (line ~519-529)
- Content area: `<div className="flex-1 overflow-auto p-4">` at SettingsDialog.tsx:561
- Inner container: `min-h-[500px] min-w-[600px]` at SettingsDialog.tsx:531
