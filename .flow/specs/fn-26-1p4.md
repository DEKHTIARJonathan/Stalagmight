# Hide markers in survey mode, show only in markers mode

## Problem

In the Global View, circular DOM markers (maplibregl.Marker instances) are always visible regardless of the current view mode. When full survey geometry (shots + stations) is displayed in survey mode, the markers clutter the view and are redundant since the geometry itself represents the systems. Markers should only be shown when the user explicitly switches to "markers only" mode via the view mode toggle.

## Key Decisions

- **Instant toggle**: Markers appear/disappear immediately when switching view modes (no fade transition).
- **Marker scope**: Only GPS-positioned systems get markers (same as current behavior).
- **Default mode**: Persisted via localStorage (`globalViewMode` key). Fresh app = survey mode = markers hidden (except loading/error states).
- **Toggle labels**: Keep current toggle button labels unchanged.
- **Interactions preserved**: Click, double-click, hover, right-click on markers all work the same in markers mode as today.
- **Tests updated in same PR**: Playwright tests that assume markers are visible in default mode must be updated.

## Survey Mode Marker Lifecycle

In survey mode, markers have a conditional lifecycle based on loading state:

1. **System added to map**: Marker shows immediately with a spinner (loading indicator).
2. **Geometry loads successfully**: That individual marker is hidden (one by one, not all at once).
3. **Geometry fails to load**: Marker stays visible as a red error indicator so users can see which systems failed.
4. **User switches to markers mode**: All markers become visible (loading, error, and loaded systems).
5. **User switches back to survey mode**: Only loading-spinner and error markers remain visible; successfully-loaded systems have their markers hidden.

### Visibility condition

In survey mode, a marker is **visible** when `geometryStates.get(filePath)?.state` is NOT `'loaded'` (i.e., `idle`, `loading`, or `error` states show markers). A marker is **hidden** only when its geometry has successfully loaded.

## Markers Mode Behavior

In markers mode (unchanged from current):
- All GPS-positioned system markers are visible.
- Survey geometry layer is hidden.
- All interactions (click, double-click, hover, right-click, context menu) work as today.

## Edge Cases

- **Mode persisted in localStorage**: If user was last in markers mode, markers show on app reopen. If survey mode, markers follow the survey lifecycle above.
- **System added after mode set**: New systems added while in survey mode should follow the same lifecycle (show spinner, hide on geometry load, keep on error).
- **System removed**: Markers cleaned up as usual regardless of mode.
- **Toggle during loading**: If user switches to markers mode while some systems are still loading, all markers become visible. Switching back to survey hides the ones whose geometry already loaded.
- **Geometry loads while in markers mode**: State tracked normally. Switching back to survey hides markers for systems that loaded while in markers mode.
- **Cancel on mode switch**: `cancelPendingLoads()` sets loading→idle. Re-entering survey mode triggers fresh geometry loads (existing behavior).

## Approach Notes

### Current effect structure (3 effects)

The existing code has two marker-related effects that will become three:

1. **Creation effect** (`GlobalViewMap.tsx:760-886`) — recreates all markers when `gpsProjects`, `selectedProjectId`, `mapLoaded`, callbacks, or `geometryStates` change. This already handles spinner creation/removal and color assignment on recreation.

2. **Styles effect** (`GlobalViewMap.tsx:888-907`) — updates marker colors (selection, error) on `selectedProjectId` and `geometryStates` changes without recreating markers.

3. **NEW: Visibility-sync effect** — toggles marker `display` style on `viewMode` changes only.

### Visibility toggle mechanism

Marker elements use inline `display: flex` (set at `GlobalViewMap.tsx:800`), so a CSS class with `display: none` would lose the specificity battle. Toggle visibility by setting `el.style.display` directly:
- **Hide**: `el.style.display = 'none'`
- **Show**: `el.style.display = 'flex'` (restore original inline style)

### How each effect handles visibility

**Creation effect** (modified): Use a `viewModeRef` (ref, not dep) to read current view mode without adding `viewMode` to the dependency array. When creating each marker element, set initial `el.style.display` based on `viewModeRef.current` and the marker's geometry state. This ensures newly created markers have correct visibility without triggering full recreation on mode toggle.

Pattern: `const viewModeRef = useRef(viewMode); viewModeRef.current = viewMode;`
Then in the effect: set `el.style.display` = `'none'` if `viewModeRef.current === 'survey'` AND `loadingState === 'loaded'`, else `'flex'`.

**Styles effect** (unchanged): Continues to update colors on selection/geometry state changes. Does NOT handle visibility.

**Visibility-sync effect** (new): Depends on `viewMode` and `geometryStates` (and `mapLoaded`). Iterates `markersRef.current` and sets `el.style.display` based on view mode and geometry state. Does NOT update colors or remove spinners — that's handled by the creation effect (which reruns on `geometryStates` changes) and the styles effect.

### Why no spinner cleanup in visibility-sync

When geometry transitions loading→loaded, the `geometryStates` dep in the creation effect triggers full marker recreation. The recreated marker will NOT have a spinner (since state is `loaded`) and will have the correct color. The visibility-sync effect also runs (since `geometryStates` changed) and hides the newly created marker if in survey mode. So spinner removal is already handled — no need for the visibility-sync effect to manage spinners or colors.

### Selection state preserved

The visibility-sync effect does NOT touch colors. The existing styles effect (`GlobalViewMap.tsx:888-907`) already handles selection (blue), error (red), and default (teal) colors correctly. When switching to markers mode, hidden markers become visible with their correct current colors.
