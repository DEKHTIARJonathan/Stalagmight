# Focus Management for DialogWrapper

## Summary

Add robust focus management to DialogWrapper.tsx — the single modal container used by all 19 dialogs in CaveChef. This centralizes focus trapping, initial focus placement, return-focus-on-close, and introduces a CSS custom property for the focus ring color.

## Problem

Currently DialogWrapper has no focus trap; Tab can escape the modal into the background page. There is no programmatic initial-focus on open, no return-focus on close, and the focus-ring color (#4ecdc4) is hardcoded in multiple CSS/TSX files instead of using a design token.

## Goals

1. **Custom `useFocusTrap` hook** — traps Tab/Shift+Tab cycling inside DialogWrapper; also traps focus inside the nested dirty-confirm `alertdialog` when it is open.
2. **Initial focus** — form dialogs focus the first `<input>` or `<textarea>`; non-form dialogs focus the primary action button.
3. **Return focus** — on close, return focus to the element that opened the dialog, gracefully handling cases where the trigger no longer exists.
4. **`--cc-focus-ring` CSS variable** — define in `index.css :root`, replace all hardcoded `#4ecdc4` focus-ring references.
5. **Spec update** — Section 11.1 of `docs/SPEC.md`: change "focus Cancel button" to "focus primary action button" for confirmation dialogs.
6. **Preserve SettingsSidebar roving tabindex** — the focus trap must not interfere with SettingsSidebar.tsx's roving tabindex on category tabs.

## Non-Goals

- Adding focus management to non-dialog components (toolbars, menus).
- Changing dialog stacking/z-index behavior.
- Adding screen-reader announcements (covered separately in Section 11.3).

## Design Decisions

### Focus Trap Strategy

Use a custom `useFocusTrap` hook rather than a third-party library. The hook:
- Accepts a `ref` to the container element.
- Queries all focusable elements (`a[href], button:not(:disabled), input:not(:disabled), textarea:not(:disabled), select:not(:disabled), [tabindex]:not([tabindex="-1"])`) on each Tab keydown.
- Wraps Tab at the last element to the first, and Shift+Tab at the first element to the last.
- Excludes elements inside `[inert]` subtrees.

### Nested alertdialog Focus

When the dirty-confirm overlay appears (alertdialog inside DialogWrapper), it gets its own focus trap instance. The outer dialog's trap is paused (the outer container gets `inert` attribute) until the alertdialog is dismissed.

### Initial Focus Heuristic

1. If dialog contains a `<form>`, focus the first visible `<input>` or `<textarea>` within it.
2. Otherwise, focus the element with `[data-autofocus]` if present.
3. Otherwise, focus the first `<button>` that is not the close (x) button.
4. Fallback: focus the dialog container itself.

### Return Focus

Store `document.activeElement` at mount time. On unmount, call `.focus()` on the stored element if it is still in the DOM. If removed, do nothing (browser default behavior).

### SettingsSidebar Compatibility

The roving tabindex pattern sets `tabindex=0` on the active tab and `tabindex=-1` on others. The focus trap's focusable-element query naturally respects this because `[tabindex="-1"]` elements are excluded. Arrow key navigation within the sidebar is handled by its own keydown handler, which is unaffected by the Tab/Shift+Tab trap.
