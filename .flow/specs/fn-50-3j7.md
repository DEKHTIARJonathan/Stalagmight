# Focus Management for DialogWrapper

## Problem

DialogWrapper.tsx is the single modal container for all 19 dialogs in CaveChef. Currently it has no focus trap (Tab can escape the modal into the background page), no programmatic initial focus on open, no return-focus on close, and the focus-ring color (#4ecdc4) is hardcoded instead of using a CSS custom property.

## Key Decisions

1. **Custom focus trap hook** — standalone `useFocusTrap(ref, options)` in `src/hooks/useFocusTrap.ts`. No third-party library. Re-queries focusable elements on every Tab keypress to handle dynamic DOM content.

2. **React portal for dialogs** — add `<div id="dialog-root"></div>` to `index.html` (static). DialogWrapper renders into it via `createPortal`. This makes `inert` sibling management trivial (everything outside `dialog-root` is the app root).

3. **`inert` on all siblings** — when a dialog opens, set `inert` on all siblings of `dialog-root` (the entire app). Standard ARIA modal pattern. Managed by a global dialog stack utility.

4. **Global dialog stack** — `src/utils/dialogStack.ts` exports imperative `push`/`pop`/`isTopmost` functions plus a `useDialogStack()` React hook. Tracks open dialog refs. On mount: push + set inert. On unmount: pop + restore inert only if stack empty.

5. **Multiple stacked DialogWrappers** — supported. Lower dialogs get `inert` when a higher one opens. Topmost dialog owns focus trap.

6. **Initial focus heuristic** — (a) first visible `<input>`, `<textarea>`, or `<select>` in the dialog, (b) element with `[data-autofocus]`, (c) first `<button>` that isn't the close X, (d) fallback: close X button. Cursor placed at end of text inputs (no auto-select).

7. **Focus primary action button** for non-form dialogs (not Cancel). Update SPEC.md Section 11.1 accordingly.

8. **Return focus** — store `document.activeElement` at mount. On unmount, call `.focus()` on stored element if still in DOM.

9. **Escape handler** — move from `document.addEventListener` (capture phase) to `onKeyDown` on the dialog element. Dialog container gets `tabindex="-1"` to ensure it can receive keyboard events. Initial focus logic guarantees focus is inside the dialog.

10. **ContextMenu excluded** — add `disableFocusTrap` prop to DialogWrapper. ContextMenu passes it. Context menus are lightweight overlays, not modals.

11. **Focus ring CSS variables** — `--cc-focus-ring` (color) and `--cc-focus-ring-offset` (offset) defined in `:root`. Root only, no per-component overrides.

12. **Focusable element selector** — comprehensive: `a[href], button:not(:disabled), input:not(:disabled), textarea:not(:disabled), select:not(:disabled), [tabindex]:not([tabindex="-1"]), [contenteditable], audio[controls], video[controls], details > summary`. Excludes elements inside `[inert]` and `[aria-hidden="true"]` subtrees.

13. **`useFocusTrap` options** — `{ enabled: boolean }` to allow conditional disabling (e.g., for ContextMenu or testing).

14. **Screen reader announcements** — rely on `role="dialog"` + `aria-modal="true"` + `aria-labelledby`. No extra aria-live announcement needed.

15. **Z-index** — keep z-50 for all dialogs. DOM order (portal append order) determines visual stacking.

16. **Playwright testing** — representative sample of 3-5 dialogs (ConfirmDialog, NewProjectDialog, SettingsDialog, dirty-confirm overlay). Use `keyboard.press('Tab')` with both `:focus` selector and `document.activeElement` assertions. Update existing tests broken by portal migration.

## Edge Cases

- Dialog with zero focusable elements (besides close X): focus the close X button
- Trigger element removed while dialog is open: skip return focus, let browser decide
- Keyboard shortcut opens dialog (no button trigger): return focus to whatever had focus (could be map canvas, table cell, etc.)
- Inline-editable table cell triggers error dialog: focus returns to the editing cell after dialog closes
- DmpSectionConfigDialog (complex layout with tabs): focus first input in active tab, following the standard heuristic
- Nested dirty-confirm overlay: gets its own focus trap instance; outer dialog gets `inert`; on dismiss, focus returns to outer dialog
- Multiple stacked DialogWrappers: each one pushes to stack, lower ones get `inert`, topmost owns focus trap

## Acceptance

- [ ] Tab cannot escape any dialog — pressing Tab at the last focusable element wraps to the first
- [ ] Shift+Tab at the first focusable element wraps to the last
- [ ] Opening a form dialog (e.g., NewProjectDialog) focuses the first text input
- [ ] Opening a non-form dialog (e.g., ConfirmDialog) focuses the primary action button
- [ ] Closing a dialog returns focus to the element that triggered it
- [ ] Stacked dialogs: only the topmost dialog is focusable; lower dialogs are inert
- [ ] Dirty-confirm overlay traps focus independently; dismissing returns focus to outer dialog
- [ ] Escape closes only the topmost dialog
- [ ] ContextMenu does not trap focus (disableFocusTrap prop)
- [ ] SettingsSidebar roving tabindex (arrow keys) works correctly inside focus trap
- [ ] --cc-focus-ring and --cc-focus-ring-offset CSS variables work; no hardcoded #4ecdc4 in focus styles
- [ ] All existing Playwright dialog tests pass after portal migration
- [ ] New Playwright tests cover: Tab cycling, return focus, stacked dialog isolation
