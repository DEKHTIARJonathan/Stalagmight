# Tool Panel Redesign & Move Tools

## Overview

Redesign the toolbar to support Photoshop-style tool groups with right-click flyouts, and add Move Segment + Move Shot tools alongside the existing Move Section and Move Station.

## Scope

- Group Pan+Zoom into a "Navigate" tool group
- Group all Move tools (Segment, Section, Shot, Station) into a "Move" tool group
- Left-click activates last-used subtool (or cycles if already active)
- Right-click opens a flyout showing all subtools
- Add Move Segment tool (moves all connected sections in real-time)
- Add Move Shot tool (moves both stations of a shot atomically)
- Surface Move Station in the toolbar UI (previously only keyboard shortcut)
- Add keyboard shortcuts for new tools

## Design Decisions (from interview)

### Move Segment Behavior
- **Drag preview**: Real-time shift of ALL connected sections during drag (not ghost/translucent). Connected section IDs are computed once at drag start via a new `get_connected_section_ids` Tauri IPC command (wrapping `Project::get_connected_section_ids()` from `project.rs:250`). During drag, a temporary visual offset is applied to all connected sections in the map render layer. On drag end, commit the final offset via the backend `moveSegment` command. The temporary offset is purely visual — no backend calls during drag.
- **Note on existing drag pattern**: The current Move Section/Move Station drag does NOT have a visual preview — it shows a toast during drag and applies the move on release. The segment drag preview is new behavior requiring render-layer offset application during `onMouseMove`.
- **Anchored segments**: Sections in anchored segments (containing zero datum) are **faded** when Move Segment tool is active and **cannot be interacted with** (no cursor change on hover, silent no-op on click). Anchored status is determined via a new `get_anchored_section_ids` Tauri IPC command (wrapping `Project::section_has_zero_datum()` from `project.rs:328`, applied to all sections to produce a set).
- **Anchor scope**: Only Move Segment respects anchoring. Move Section and Move Station remain unrestricted.

### Move Shot Behavior
- Moves BOTH stations of the clicked shot (from-station and to-station) by the same offset
- **Atomic undo (mandatory)**: Move Shot MUST use `execute_batch` with `Command::Batch` (defined at `command.rs:98`, logic at `commands.rs:642`). The backend Tauri IPC for `execute_batch` does NOT currently exist — it must be created in Task 2 (the frontend `projectStore.ts:855` already has the `executeBatch()` call but it's dead code without the backend). The frontend `BatchCommand` type (`commands.ts:68`) must be extended with a `move_station` variant. There is NO fallback to sequential `moveStation` calls — the batch path is the only path.
- Station 0 (section origin) is allowed — applies station offset like any other
- Virtual shots are also moveable

### Toolbar UI
- **Separators**: Thin vertical lines between tool groups: `[Select] | [Navigate▾] | [Draw][Delete][Merge][Measure] | [Move▾]`
- **Group indicator**: Small triangle (▾) in bottom-right corner of grouped buttons
- **Left-click**: If group inactive, activate last-used subtool. If already active, cycle to next subtool.
- **Right-click**: Open flyout showing all subtools with icon + name + shortcut

### Flyout Accessibility
- Full keyboard navigation: Arrow keys to move between subtools, Enter to select, Escape to close
- `data-testid="subtool-flyout-{groupId}"`

### Keyboard Shortcuts
- `V` = move_segment (reassigned from move_section)
- `Shift+V` = move_section
- `G` = move_shot (new)
- `T` = move_station (unchanged)

## Implementation Order

1. Task 1: Type System & Tool Group Definitions (foundation)
2. Task 2: Backend — MoveSegment Command + Query IPCs (MoveSegment command, get_connected_section_ids IPC, get_anchored_section_ids IPC)
3. Task 3: Keyboard Shortcuts (config changes)
4. Task 4: Frontend Move Tool Handlers (wire up move_segment with real-time drag preview, move_shot drag with batch commit, anchored fading)
5. Task 5: Toolbar UI - Tool Group Buttons (visual changes, depends on Tasks 1-4)
6. Task 6: Tests (after all functionality works)
