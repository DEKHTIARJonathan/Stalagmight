# Loading Progress Indicator

## Problem

When loading a project, the UI currently displays only a simple "Loading..." text with no indication of:
- What operation is currently happening
- How much progress has been made
- How long the user might need to wait
- Whether any errors occurred

This is especially problematic for larger projects where loading can take noticeable time, leaving users uncertain about application state.

## Approach

Implement a comprehensive loading progress system with:

### 1. Visual Design

**Location**: Centered in screen (same position as current "Loading...")

**Layout**: Compact card (~300-400px wide) containing:
- Project name at top ("Loading ProjectName...")
- Overall progress bar (weighted by phase)
- Current phase text with action-based labels
- Per-phase progress bar (determinate or indeterminate)
- Item counts where applicable (e.g., "23/50 stations")
- Cancel button below progress bars

**Style**:
- Subtle/minimal design using theme colors (accent color for bars)
- Thin progress bars, muted colors
- Subtle shimmer/pulse animation on active bars to indicate work
- Smooth transitions for progress updates
- Modal behavior (blocks other interactions)

### 2. Backend Progress Events

**Event System**: Tauri events with typed struct

```rust
#[derive(Clone, Serialize)]
pub struct LoadingProgress {
    pub phase: LoadingPhase,
    pub phase_label: String,        // User-friendly label
    pub current: Option<u32>,       // Current item (for granular progress)
    pub total: Option<u32>,         // Total items (for granular progress)
    pub overall_percent: f32,       // Weighted overall progress 0-100
    pub is_indeterminate: bool,     // True for non-measurable phases
}

#[derive(Clone, Serialize)]
pub enum LoadingPhase {
    OpeningDatabase,
    LoadingProjectData,
    LoadingSections,
    ComputingStations,
    ComputingStatistics,
    ValidatingData,
    LoadingSettings,
    Finalizing,
    // For project creation
    CreatingDatabase,
    InitializingProject,
    SavingSettings,
}
```

**Event name**: `loading-progress`

**Granular progress**: Emit events during iteration loops (every N items) for smooth progress bar updates in:
- Loading sections/shots from database
- Computing station coordinates
- Computing statistics

**Cancellation**: Use cancellation token passed to backend, checked between phases

### 3. Phase Weight Distribution (for overall progress)

| Phase | Weight | Granular Progress |
|-------|--------|-------------------|
| Opening database | 5% | Indeterminate |
| Loading project data | 25% | By item count |
| Loading sections | 15% | By section count |
| Computing stations | 20% | By station count |
| Computing statistics | 15% | By section count |
| Validating data | 10% | Indeterminate |
| Loading settings | 5% | Indeterminate |
| Finalizing | 5% | Indeterminate |

### 4. Phase Labels (Action-based)

- "Opening database..."
- "Loading survey data..."
- "Loading sections..."
- "Calculating station positions..."
- "Computing statistics..."
- "Validating data..."
- "Loading display settings..."
- "Finalizing..."

For project creation:
- "Creating database..."
- "Initializing project..."
- "Saving settings..."

### 5. Frontend Implementation

**New Component**: `LoadingProgress` (reusable for other operations)

Props:
```typescript
interface LoadingProgressProps {
  title: string;                    // "Loading ProjectName..."
  phase: string;                    // Current phase label
  phaseProgress?: number;           // 0-100 or undefined for indeterminate
  phaseCurrent?: number;            // e.g., 23
  phaseTotal?: number;              // e.g., 50
  overallProgress: number;          // 0-100
  onCancel?: () => void;            // Cancel handler
  error?: {
    message: string;
    details?: string;
  };
}
```

**State Management**: Add to projectStore or create dedicated loadingStore:
```typescript
interface LoadingState {
  isLoading: boolean;
  projectName?: string;
  phase?: string;
  phaseProgress?: number;
  phaseCurrent?: number;
  phaseTotal?: number;
  overallProgress: number;
  error?: { message: string; details?: string };
  cancellationToken?: string;
}
```

### 6. Error Handling

**Error State UI**:
- Progress bar turns red/error color
- User-friendly error message displayed
- Expandable technical details
- Action buttons: Retry | Dismiss | Copy Error

### 7. Edge Cases

- **Already open project**: Show brief "Already open" message, skip loading
- **Fast loading**: Always show progress UI (no minimum display time skip)
- **Cancel during load**: Immediately discard all partial state, return to GlobalView
- **Backend continues after cancel**: Frontend ignores remaining events

### 8. Accessibility

- ARIA labels on progress bars
- Live region announcements for phase changes
- Keyboard accessible cancel button
- Screen reader friendly progress updates

### 9. Testing

- Expose via `__E2E_TEST__` for E2E testing
- Debug level logging for progress events
- Unit tests for LoadingProgress component
- E2E tests for full loading flow
