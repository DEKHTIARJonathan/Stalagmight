# Progress Update: WebdriverIO Tests Fixed

## Issues Found and Fixed

### 1. Test Hang - View Not Switched
**Problem**: After `resetAppState()` sets view to 'global', `loadFixtureProject()` opened the project but didn't switch to SingleSystemView. MapCanvas wasn't rendered, so `window.__cavechef_map__` was never set, causing `waitForMap()` to hang.

**Fix**: Added `setView('single')` call after `openProject()` in `loadFixtureProject()`:
```typescript
if (result.success) {
  e2e.uiStore.getState().setView('single');
}
```

### 2. Ctrl+Drag Not Working in WebdriverIO
**Problem**: WebdriverIO's `performActions` with keyboard keys doesn't reliably trigger the app's keyboard event listeners in WebKit/Tauri. The Ctrl key state wasn't being maintained.

**Fix**: Use JavaScript `KeyboardEvent` dispatch instead of WebdriverIO key actions:
```typescript
await browser.execute(() => {
  const event = new KeyboardEvent('keydown', {
    key: 'Control',
    code: 'ControlLeft',
    ctrlKey: true,
    bubbles: true,
    cancelable: true,
  });
  window.dispatchEvent(event);
});
```

### 3. Station Position Test Bug
**Problem**: The test expected stations to move LEFT (negative) when dragging right, but they actually move RIGHT (positive) in screen coordinates.

**Fix**: Corrected the expectation:
```typescript
// Drag right → stations move right in screen coords (positive screen X)
if (movementX > 50) {  // Was: movementX < -50
```

## Key Learnings
1. When opening a project via store in tests, must also set the UI view
2. WebdriverIO keyboard actions may not work with WebKit/Tauri - use dispatchEvent
3. Map panning moves content WITH the drag direction in screen coordinates
